# Brightseed copy and SEO review

Reviewed 9 November 2026. Brightseed should lead with websites, web apps and AI. The current site primarily sells software outsourcing and mobile development, so its positioning does not reflect the offer described for the brand.

This review covers the current working-tree homepage, five project summaries, services, pricing, testimonials, shared navigation and footer, contact page, blog index, all 11 published articles, privacy and terms pages, and the SEO implementation. The unpublished example was checked separately. Recommendations below are proposals; the website content has not been changed.

Source findings were cross-checked against the existing local build where useful. The production homepage, robots.txt and sitemap could not be fetched through the browsing tool. Production status, indexing, traffic and Core Web Vitals therefore remain unverified. Existing uncommitted work was preserved.

## SEO findings and implementation recommendations

### Crawlability and discovery

**Blog archive:** `components/article-list.js` renders four entries initially and expands the list only on a button click. `pages/blog.js` repeats the newest three above it. The existing built HTML confirms only four unique article links. Older posts are generated as routes, but generation alone does not make them discoverable. Render all 11 links, or add server-rendered pagination with real page URLs and anchor links. Google documents that crawlers do not click these buttons. [Google pagination guidance](https://developers.google.com/search/docs/specialty/ecommerce/pagination-and-incremental-page-loading).

**Sitemap:** No sitemap file, route or generation configuration was found. Generate one from canonical static routes and published posts; exclude drafts and error pages and use meaningful modification dates. Submit it through Search Console after deployment. A sitemap assists discovery; it does not guarantee indexing. [Google developer SEO guidance](https://developers.google.com/search/docs/fundamentals/get-started-developers).

**Robots:** No robots.txt implementation was found. Add a deliberate production policy and sitemap reference. A missing robots.txt is not itself an indexing block. Verify production robots and HTTP headers, and keep previews protected from indexing through hosting controls or appropriate indexing directives.

**Links and URLs:** Correct the two old-IP contact links. Standardise internal `/blog/` and `/contact/` links to the chosen canonical style to reduce redirects. Keep the existing permanent redirect for the encoded JavaScript article slug. Check historic URLs and external project links before a relaunch; do not redirect unrelated deleted articles to the homepage.

### Titles and page structure

`components/page-seo.js` already outputs titles, descriptions and absolute canonicals. These are foundations to improve, not missing features. The HTML language is already set, posts are statically generated, and unknown post slugs return 404.

Replace vague titles with accurate service or topic descriptions. Google recommends clear, concise titles that match the page; it may generate a different title link. [Google title guidance](https://developers.google.com/search/docs/appearance/title-link).

| Page | Proposed full title |
| --- | --- |
| Home | Websites, Web Apps & AI Development \| Brightseed |
| Blog | Web Development & AI Insights \| Brightseed — use when the editorial content supports it |
| Contact | Discuss Your Website, Web App or AI Project \| Brightseed |
| Website service | Website Design & Development \| Brightseed |
| Web app service | Custom Web Application Development \| Brightseed |
| AI service | AI Development & Integration \| Brightseed |

When implementing, pass only the page-specific portion into `PageSeo`, which already adds the brand suffix.

The navbar and footer brand are H1s, as are contact banners and “Thanks for reading”. The existing build has four H1s on the homepage and three on the blog/contact/policy pages. Use a clear main page heading; make brand links and decorative copy ordinary elements and section headings H2s. Multiple H1s are not an automatic ranking penalty, but this structure obscures the page's main subject. Several article bodies also use H1s under an existing article H1.

### Missing service pages and evidence

Create `/services/website-development`, `/services/web-app-development` and `/services/ai-development` with distinct, substantial content. Each should explain the buyer's problem, intended users, deliverables, process, examples, constraints and next step. Add internal links from the homepage, relevant case studies and articles. Treat these terms as positioning hypotheses, not measured keyword-volume findings.

Add an About page with the actual people, business identity and delivery model, plus individual case-study pages. Link author names to meaningful profiles. If location-based work is a priority, confirm the genuine operating area first; avoid interchangeable city pages.

### Structured data and sharing

No JSON-LD was found. Add Organization data with verified name, URL, final logo and genuine social profiles. This can help Google understand and distinguish the business. [Organization documentation](https://developers.google.com/search/docs/appearance/structured-data/organization).

For articles, add BlogPosting data with headline, canonical URL, author/profile, suitable images, original publication date and genuine modification date. Preserve original date information and extend the content model rather than replacing publication dates. [Article documentation](https://developers.google.com/search/docs/appearance/structured-data/article).

Use breadcrumbs when a corresponding visible hierarchy is introduced. Validate structured data; do not promise rich results or add unsupported review ratings.

Open Graph and Twitter card tags are absent. Add per-page title, description, URL, type and a suitable share image, with image alt text. These improve sharing presentation; they are not a substitute for useful content. Create a separate share graphic with a deliberate background rather than relying on a transparent wordmark alone.

### Images and performance

Project screenshots and client logos generally have empty alt text. Describe informative screenshots and name clients where appropriate; leave decorative background images and redundant service icons empty. Replace generic “Cover Image for ...” alt text with a content-aware description where useful. Do not stuff keywords into alt attributes.

`components/home-slider.js` eagerly renders all five poster images and autoplays the active video. This is a performance risk to measure, not a measured Core Web Vitals failure. Consider a single static hero, loading only necessary media, and reduced-motion behaviour. Check article images for intrinsic dimensions and oversized downloads. The repository's total media size does not equal the amount transferred on one page view.

### AI search and measurement

Prioritise clear service explanations, indexable pages, original examples and accurately attributed expertise. Google states that its AI search features use the same SEO foundations and do not require special optimisations. Do not treat `llms.txt` or a special “AI schema” as a missing Google requirement. [Google AI search guidance](https://developers.google.com/search/docs/appearance/ai-features).

Verify Search Console ownership and review indexed pages, queries, clicks and impressions. Ownership cannot be inferred from the absence of a verification meta tag because DNS verification is possible. Confirm existing analytics before adding another system. If measuring email-link clicks, label them as clicks rather than completed enquiries; qualify actual leads separately.

## Suggested delivery order

1. Correct misdirected contact links, inaccurate claims and obvious copy errors. Agree the core services and intended audience.
2. Publish the revised homepage and three service pages, supported by selected work and a clearer contact route.
3. Make every article crawlable, add the sitemap and metadata extensions, and simplify heading structure.
4. Refresh the development-partner, app-cost, JavaScript and social-network guides first. Decide whether crypto and vertical mobile topics support the current business before investing further.
5. Add practical AI material backed by real work: how to choose a useful automation task, integrate AI into an existing app, and evaluate whether a prototype is reliable enough to use.
6. After deployment, check HTTP status codes, redirects, canonicals, robots directives, sitemap URLs, mobile layout, sharing previews and structured data. Measure performance with PageSpeed Insights and review search and enquiry data over time.

The remaining business inputs are the target client profile, genuine geographic market, current delivery model, current service scope, verified project outcomes and commercial terms. They will sharpen the draft without changing the immediate technical priorities.
